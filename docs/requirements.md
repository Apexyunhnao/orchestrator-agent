# 需求文档 — 智能客服统一入口（Supervisor模式）

## 业务背景

一个 Supervisor Agent 作为智能客服总控，协调两个子 Agent：

- **RAG Agent**（:8002）：客服政策知识库（退货/退款/换货/物流政策）
- **客服工单 Agent**（:8001）：工单处理（查订单/改地址/退差价/催物流）

两个 Agent 服务同一个场景：电商售后。用户一句话可能既需要查政策又需要办业务——"退货要几天，帮我把 ORD-2001 退了"。

## 核心能力

Supervisor 不是一次性分类→转发，而是**多轮逐步决策**：

1. 收到用户消息 → 思考：需要先查退货政策
2. 调用 RAG → 拿到政策结果
3. 再思考：用户还要退单，调客服 Agent
4. 拿到工单结果 → 思考：信息齐全，合成回答

## 成功指标

| 指标 | 定义 | 目标 |
|------|------|------|
| 任务完成率 | 多轮后正确完成用户全部诉求 | ≥ 80% |
| 工具选择准确率 | 每轮选择的工具符合预期 | ≥ 85% |
| 端到端耗时 | 从发消息到最终回答 | ≤ 15 秒 |
| 降级可用性 | 单子Agent宕机时仍返回部分结果 | 不整体500 |

## MVP 范围

### 做
- LangGraph Supervisor 状态图
- 两个工具：query_rag / create_ticket
- 多轮决策：调完RAG拿到结果后可以再调客服
- 最终合成：汇总两个Agent的结果
- 30条多轮场景测试集
- FastAPI + Web页面

### 不做
- 超过2个子Agent
- 工具调用并行化（按需串行）
- 人工介入（HITL）
